Introduction What is the essential story being told by your site and what type of structure did you choose to implement?

In searching for the topic of my final project website I considered topics which were interesting to me. I also considered if the website I create, would be useful to me or for someone else, or would I continue to use it after project submission? My website is called Warsaw City Funclub. The main idea behind it is to gather useful information about interesting places in the Polish capital. Very often in my time free of work I think about what I could do during the day with my wife, children or alone. I have been living in Warsaw for around 10 years, however, despite that, it is nice to have some kind of list of places I like. My website contains a list, or actually, webpages of major touristic attractions and interesting cafes. Both lists are relatively easy to expand.

  • Must see page contains turistic atractions or interesitng places in general.
  • Cafes page contain list of cafes in the city center area. I spent a lot of time in different cafes as part of my study routine. Sometimes I can't learn at home as my children aged 5 years and 1-month old attract my attention too much. A solution is to study somewhere else.
  • Photos page contains photos of different parts of the city. In search of an interesitng place to visit, seeing a photo can inspire where to go.

Inspiration State 3 things that have inspired you when creating your website (e.g. guest speakers, websites, artists, blogs).

The obvious inspiration was the Web Development module lectures and materials provided there. By studying the lectures and related materials I was able to create a basic structure and functionality for my website. The grid layout, hiding navigation menu, responsive design, and progress bar were all inspired by the lectures. Also, the use of handlebars.js to create templates was inspired by the module videos. Sometimes I needed to find some supporting materials online. Mostly I used w3schools.com website and less often the YouTube. A thing which was completely outside of lectures scope was implementation of BEM (Block, Element, Modifier) - a component-based approach to web development, where the idea behind it is to divide the user interface into independent blocks. I found this concept very helpful in organising the HTML code and also how to name each HTML element. The element naming convention recommended by the BEM model significantly simplified for me the structure of the HTML and CSS.
Another inspiration was general principles of the design. One of the links provided in the reading section lead to the website 9 Guidelines & Best Practices for Exceptional Web Design and Usability where the following principles of the design were recommended:

  1. Simplicity
  2. Visual Hierarchy
  3. Navigability
  4. Consistency
  5. Responsivity
  6. Accessibility
  7. Conventionality
  8. Credibility
  9. User-Centricity

I tried to use a simple design, where it is easy to find the content and navigate. The look and functionality of my web pages are similar across the whole website. The design is responsive. There are three levels of responsivity: mobile, tablet and desktop. I introduced accessibility options and the layout of the site is conventional - there are no unusual layouts or elements. The information provided here is accurate and useful.
I also tried to follow the Flat Design 2.0 principles, by using simple shapes and solid colours, while introducing only shadows to add a bit of the impression of the third dimension.

Accessibility State 3 ways in which your site is accessible to those with different abilities and needs (for example those with visual impairment)

I introduced the following accessibility items:

  1. An option to select three different sizes of font. It affects all the elements of the website. The font gets significantly larger when the largest option is selected.
  2. An option to change the display colour to dark mode, particularly useful during the night. Some elements changes in the same way, while other have specific style related to the dark mode. All images dim slightly when dark mode is in use.
  3. I used proper contrast between the text and the background items.
  4. Whitespaces are used to make the website more readable and easier to navigate
  5. I used the proper semantic structure of the website and used descriptive headings to each section to make it easier to navigate using a screen reader.
  6. I provided alternative image descriptions for the images in the case the user uses a screen reader or the image failed to download.

Usability State 3 ways in which you considered the usability of your site

  • By the design, my website was meant to be useful. As mentioned in the introduction I wanted this website to be useful to me or other users. The content there is relevant for the website topic and up to date. The content may be interesting and useful for any user.
  • Responsive design made the website useful on all ranges of devices. It remains useful up to 400% zoom in the browser. No element will overlap with the other and no text will go beyond its block element
  • It is possible to print each page directly from the webpage by clicking the "Print" button. Each page has a @media query, especially for printing. Printed pages can easily be used instead of electronic device.

Learning State 3 things you had to learn or find out to create your site. How did you achieve that?

  • I had to learn from the external resources how to make common HTML for all pages to be stored in a separate file. I found out that using the handlebar's partials can be used to make this possible. Handlebars were discussed extensively in lectures, however, it was not mentioned how to achieve such effect. I tried to use the w3 script for that task, however, it did not work correctly for all elements.
  • Using mentioned in the introduction BEM model for naming the elements and styling them. This was nowhere mentioned during the lectures. I had to spend a significant amount of time studying available BEM documentation to implement it in a useful way. The BEM model made the transfer of the elements across the website very easy. My previous method made it very complicated.
  • I learned how to use the flex property to position the elements in the container. It was particularly useful to make the responsive Photo gallery on Photos webpage. I used for that the w3schools instructions and flex property description.

Evaluation II What aspects of your work could be improved? How might you do things differently another time?

  • In general, I am happy with what the website looks like and how it works. I was not able to prepare the last, 5th webpage. I planned to introduce the Map page, where all the places in the data files could be displayed.
  • Another improvement which I would like to introduce is the ability to control the website using a keyboard. At this stage I did not introduce any code which would handle the keyboard inputs.
  • The last important thing which I would like to consider is to provide some kind of backup page in the case the user has JavaScript blocked. Now the whole page relies on scripts to work correctly. I think that it is a demanding part of Web Design to make the website work even if the scripts are prevented from working.
  • I would also introduce handlebars precompiled files on my website to avoid compiling the code each time I use any webpage.
  • I would add more comments if I had more time. I commented only on code which which was unusual or important not to modify it without the need.
  • My idea was to enable the user to add his Must See places, Cafes or Photos on each of the pages using form tags. I think that this would require a significant amount of research for me to be able to implement such functionality.
